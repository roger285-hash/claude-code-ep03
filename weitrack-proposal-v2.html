04

三階段建構計畫

第一階段 0 – 30 天
雛形提案

05

與網緹的合作期待

致廖先生
👥
四方角色分權
支援不同角色登入與視圖隔離，不同使用者看到對應資訊，期待與您討論最適合的權限架構。
📱
手機查詢介面
買家端 RWD 響應式設計，操作直覺，手機體驗優先，歡迎您提供現有設計建議。
💬
LINE 推播串接
支援 LINE Official Account 或 Notify API，希望與您確認整合到第三階段的可行路徑。
🔌
API 串接確認
希望了解現有後台系統的 API 能力，避免重複建置資料層，這是我們最希望第一步確認的事項。
💰
報價與時程討論
初期建置費、月費與維護費，希望在一個月雛形期限內共同找到合適的合作模式。
📍
本地溝通效率
台灣在地團隊，溝通效率高，我們希望保持密切聯繫，快速響應每一個決策節點。
06

關鍵風險與對策

⚠️資料斷點
先定義每節點責任人與掃碼時機，確保全程狀態不中斷。
⚠️單號規則混亂
建立統一主單號邏輯，子單號對應，與偉翔內部對齊設計規則，再共同確認。
⚠️買家習慣養成
同步設計客服引導話術，主動推廣 LINE 查件管道。
07

我們希望一起確認的事項

確認現有 API 能力
現有系統是否有查詢 API 或公開查詢頁功能，評估擴充可行性，以決定後續技術路線。
對齊單號規則
確定主單號設計方式，子單號對應邏輯，統一全系統識別基礎，避免後續開發混亂。
規劃推進節奏
共同討論三階段的推進節奏與溝通頻率，讓雙方都能掌握進度，即時調整方向。
