05 開發商評估標準
👥
四方角色分權
支援不同角色登入與視圖隔離，不同使用者看到對應資訊。
📱
手機查詢介面
買家端 RWD 響應式設計，操作直覺，手機體驗優先。
💬
LINE 推播串接
支援 LINE Official Account 或 Notify API，能整合到第三階段。
🔌
API 彈性
可與網緹現有後台系統 API 串接，避免重複建置資料層。
💰
報價與時程
初期建置費 + 月費 + 維護費，需符合一個月雛形期限。
📍
本地支援能力
台灣在地團隊，溝通效率高，快速響應異常處理需求。
06 關鍵風險與對策
資料斷點
先定義每節點責任人與掃碼時機，確保全程狀態不中斷。
單號規則混亂
建立統一主單號邏輯，子單號對應，與奕迪對齊設計規則。
網緹不配合
先確認 API 能力，再決定擴充現有系統或另覓開發商。
買家習慣養成
同步設計客服引導話術，主動推廣 LINE 查件管道。
07 本週待確認事項
確認網緹 API 能力
現有系統是否有查詢 API 或公開查詢頁功能，評估擴充可行性。
與奕迪對齊單號規則
確定主單號設計方式，子單號對應邏輯，統一全系統識別基礎。
接觸第一家開發商
觀察現有作業流程，畫出流程圖草稿，開始外部開發商接觸。
